# 融云 IM 应用层规则

当请求包含 IMLib 或 IMKit 本身不强制执行的时间窗口、字符限制、角色权限或触发规则时加载本文件。此类检查通常由应用层实现，并可配合服务端规则防止篡改。

## 快速分类

| 要求 | SDK 是否强制 | 推荐分层 |
| --- | --- | --- |
| 发送后 X 分钟内可编辑 | 否 | 客户端负责体验，服务端负责校验 |
| 发送后 X 分钟内可全员撤回 | 否 | 客户端负责体验，服务端负责校验 |
| 仅管理员可置顶/禁言/全局禁言 | 部分 | 将应用角色映射为融云支持的群组权限或应用自有权限，并在客户端和服务端校验 |
| 文本长度 ≤ N | 否 | 编辑器校验；签名消息时服务端再次校验 |
| @ 用户数量上限 | 否 | 编辑器校验 |
| 双击头像 @ 用户 | 否 | 应用交互调用 IMKit 的提及插入 API |
| 点击姓名 @ 用户 | 否 | 应用交互调用相同 API |
| 自定义消息包含用户卡片载荷 | 是，可通过自定义消息类型 | 注册类型并渲染，载荷结构由应用定义 |
| 隐藏特定会话类型 | 否 | 在列表查询/渲染层过滤，不改变同步范围 |
| 显示“已读 N / 未读 N” | 单聊/群组支持 | 用 SDK 已读回执取数值，由应用渲染格式 |

## 编辑时间窗口

先确认目标会话类型和当前 SDK 版本支持消息修改，再使用官方文档中的消息修改 API 与发送时间字段。长按或菜单触发时检查业务设定的编辑窗口；通过后调用已验证 API，并在存在修改时间字段时显示“已编辑”。服务端应拒绝超过窗口的更新。

不要用“撤回后重新发送”模拟编辑，这会丢失消息身份、顺序和已读状态；也不要只信任客户端时钟。多设备编辑成功后，应通过 SDK 的标准消息更新事件让其他设备刷新。

## 全员撤回时间窗口

IMLib 对撤回时间不做限制，IMKit 默认撤回时间为 2 分钟且可配置。应用需要自定义窗口时，应先读取目标平台的撤回文档，使用该版本公开的撤回 API 和消息发送时间字段；不要复用其他 SDK 的方法名。服务端应再次拒绝超过业务窗口的请求。

## @ 提及触发

SDK 支持消息中的提及信息，但触发方式由应用定义：在编辑器输入 `@` 打开成员选择器；点击姓名或双击头像插入 `@<name>`；长按头像可显示含 @ 的快捷反应菜单。

始终以结构化提及数据保存被提及用户 ID 和原文，不能只保存纯文本，否则提及通知和“@我”筛选会失效。仅在支持提及的会话类型启用：群组 ✅、超级群 ✅、单聊 ❌、聊天室 ❌。Web IMKit 应使用文档化的提及插入 API，不要直接修改编辑器 DOM。

## 会话列表过滤

如果产品只想显示部分会话类型，必须在**渲染层**过滤：

- ✅ 渲染前过滤列表查询结果。
- ✅ 通过文档化 hook 隐藏 IMKit 会话列表中的行。
- ❌ 不要删除底层会话。
- ❌ 不要取消隐藏会话的消息事件订阅，否则未读数和通知会失效。

如果用户真正想移除会话，应确认是仅删除本地会话、退出群组，还是由服务端解散群组，并参考基础功能指南的术语。

## 头像与气泡视觉规则

方形圆角头像、按角色设置气泡颜色、调整密度等纯视觉变化属于应用层。IMKit 优先使用主题 token、CSS 变量和文档化的组件定制点；IMLib 自定义 UI 直接在应用组件中实现。IMKit Web Components 经常锁定布局方向，详见 `integration-workflow.md` 的“受限”分类。

## 验证规则

每条应用层规则都要加入测试清单：在适用时用篡改请求绕过客户端检查并确认服务端拒绝；多设备确认编辑/撤回同步；确认规则不会悄悄应用到不支持底层 SDK 能力的会话类型。
