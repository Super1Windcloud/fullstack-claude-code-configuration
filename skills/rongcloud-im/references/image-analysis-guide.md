# 视觉 SDK 功能识别指南

本文说明如何根据即时通讯截图、UI 原型和产品参考图，识别用户希望集成的融云 IMLib 或 IMKit 能力。

默认先分析可见的产品行为，再映射到 融云 im 的规范术语和集成表面，最后判断用户是在询问解释、实现方案还是代码变更。不要把每张图都当作 AI 视觉/OCR 集成请求。

## 非聊天截图分流

| 可见界面 | 分类 | 响应规则 |
| --- | --- | --- |
| 登录、注册、手机号、二维码、密码、2FA、“保持登录” | 应用认证 | 说明 IM SDK 只接收服务端 Token，不虚构 SDK 登录 API；必要时引用 `credentials-and-token.md` |
| 营销页、下载页、应用商店页、竞品品牌启动页、Mobbin 水印 | 非 SDK 产品外壳 | 从功能映射中丢弃，不复刻竞品品牌 |
| 通话控制、会议、屏幕共享、录制 | 跨技能/范围外 | 从 IM 中拆出并转到融云 RTC/CallKit 或技术支持；时间线中的通话记录卡仍可作为 IM 自定义消息 |
| 与消息无关的设置页 | 通常是应用外壳 | 只提取与 IM 相关的设置，否则询问目标 IM 功能 |

若图片不是 IM 集成表面且用户没有提供 IM 需求，解释分类后停止，并提出一个简短追问。

## 即时通讯截图功能识别

用户提供即时通讯产品截图并询问“这个功能是什么”“如何集成”等问题时，按以下顺序分析；除非用户明确要求实现且集成范围已确认，否则不要写实现代码：

1. **可见 UI 上下文**：识别会话列表、消息线程、编辑器、媒体预览、消息操作菜单、置顶区域、搜索、通话控制或通知状态，说明关键元素及其与当前操作的关系。
2. **核心 SDK 功能**：使用规范 IM 术语命名能力，例如消息转发、隐藏发送者、修改收件人、转发预览、回复、消息置顶、媒体/语音/文件消息、已读回执、未读数、搜索、成员管理、审核或会话导航。
3. **SDK/IMKit 映射**：小范围私聊通常对应单聊或群组会话；大型社区、论坛、公会和子频道对应超级群及其频道；在线临时活动对应聊天室。通话、会议和音视频控制需转到融云 RTC/CallKit。
4. **集成表面拆分**：说明触发、中间状态、确认/取消、最终结果及隐私权限；指出消息菜单、编辑器扩展、列表项、消息单元格、频道头部、成员列表、通知处理、事件监听、自定义消息、消息扩展或应用服务端 API 等表面。
5. **验证要求**：分析请求不生成代码；实现请求先完成范围确认，并从官方文档、已安装包或现有项目验证准确 API、属性、事件和消息字段。使用 IMKit 时遵循 `integration-workflow.md` 的截图实现规则。

默认分析模板：

```markdown
此图片展示：[功能名称]

关键功能：

...
对应的融云 IMLib 功能：

...
集成注意事项：

...
```

## 多截图批处理

当用户提供 2 张或更多截图时，不要逐张套用单图模板：

1. 用一张表清点所有截图：`Screen | Subject（≤ 5 个词）| Tag`。标签为 `chat`、`auth`、`marketing`、`call`、`media`、`composer`、`menu`、`settings`、`other`。
2. 丢弃 `marketing`、第三方品牌元素和水印，并只说明一次。
3. 将所有 `auth` 截图合并为一句：登录/注册/2FA/二维码登录属于应用层；IMLib 只接收服务端 Token，不重复计为 IM 功能。
4. 将 `call` 截图放到范围外部分，并明确建议融云 RTC/CallKit。
5. 合并同一功能的不同状态（例如表情选择器开关、定时菜单和列表）。
6. 输出一份汇总功能表：`Feature | Source screen(s) | Layer | Notes`，层级使用 Built-in、Configurable、Constrained、Application chrome、Application-layer、Application-server、Pending review、Cross-skill、Out-of-scope，并参考 `feature-pattern-map.md`。
7. 用户未明确要求实现时停止；要求实现时，将汇总表交给 `integration-workflow.md` 的“截图驱动实现”流程。

该流程避免用户一次提交竞品截图集合时产生重复分析。
