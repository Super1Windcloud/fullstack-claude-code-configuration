# 融云 IM 集成工作流

当 SKILL.md 的分流流程将请求归类为**集成**时加载本文件。此时术语规范化和范围检查已经完成。

## 执行步骤

1. 项目识别：从项目文件推断平台/SDK，并阅读 `references/platform-setup/` 下对应平台文件。
2. 输入确认：确认无法推断的输入。
3. 文档与代码验证：获取官方文档，再用已安装代码确认细节。
4. 决策框架：按五层决策流程选择并记录层级。
5. 实现前置检查：确认 IMKit 就绪状态、UI 组件所有权和自定义 UI 实现方案。
6. 实现：按以下规则生成代码。
7. 测试与验证：提供验证步骤。
8. 最终待办：输出已实现/未实现总结。

## 项目识别

在向用户提问前，先检查本地项目：

| 平台 | 检查文件 |
| --- | --- |
| Android | `build.gradle`、`settings.gradle`、Gradle 模块文件 |
| iOS | `Podfile`、`*.xcodeproj`、`Package.swift` |
| Web | `package.json`、`tsconfig.json`、框架配置文件 |
| Flutter | `pubspec.yaml` |

用 `rg` 搜索初始化封装、已安装包和版本、IMKit 定制点、Token 获取逻辑、本地化和 UI 文案规范。识别平台后先阅读对应平台导航文件，再确认 SDK/会话类型选择。

## 输入确认

写集成代码前必须确定**平台、会话类型、业务场景**。SDK 选择只有在用户明确指定时才是输入约束，否则由五层决策框架决定。用户明确选择 IMLib 时记录该约束并从第 3 层开始，不再执行 IMKit 的第 1、2 层评估；只有需要切换到 IMKit 时才说明权衡并获得同意。优先从项目和用户描述推断；无法推断时只问一个简短问题。多会话类型需求要说明每种类型的职责。现有融云初始化、连接或会话使用视为已确认，只询问新增或变更值。

凭据前置条件：可运行初始化需要 App Key 和 Token；绝不能在客户端放 App Secret、签名逻辑或特权 Token 生成代码；缺 App Key 时索取或提供明确的不可运行脚手架；缺 Token 时接入服务端变量或标记占位符。

## 文档与代码验证

**文档优先**：先从 `references/llms.txt` 搜索相关路径，运行 `bash scripts/fetch-docs.sh <path>`，完整阅读 `references/cache/` 中的官方指南，然后才检查已安装 SDK 的类型、源码和包内部。不要只凭类型定义逆向推断流程。

能力边界、首次支持版本或文档入口类判断，先阅读 [IM SDK 功能清单使用规则](./feature-lists.md)，按平台和 SDK 获取对应清单，再获取清单指向的功能页并对照项目 SDK 版本。

网络不可用且没有缓存时，可使用已安装代码和本地项目，但将不确定的 API、初始化顺序或集成方式标为“待文档复核”。文档与代码冲突时，按已安装版本实现并简要说明冲突；没有来源确认的细节不得编造。

## SDK 集成决策框架

实现前阅读 [SDK 集成决策框架](./sdk-integration-decision-framework.md)，根据用户的 SDK 约束选择入口：

1. 未指定 SDK：从第 1 层 IMKit 原生能力开始，再依次评估 IMKit 定制扩展、IMLib API 层和后续层级。
2. 指定 IMKit：评估第 1、2 层；若仍无法满足，先说明限制并获得用户同意，才能进入第 3 层 IMLib API 层。
3. 指定 IMLib：跳过第 1、2 层，从第 3 层 IMLib API 层开始。
4. IMLib 无法满足且需要切换到 IMKit：解释权衡并获得用户同意后，再进入相关 IMKit 层级。
5. 源码修改需用户明确批准；最终决策为实现、替代方案或报告不支持。

## 实现规则

遵循项目已有代码风格、目录结构、状态管理和 UI 约定。IMLib 自定义 UI 要按已验证 API 完成初始化、连接、会话打开、消息收发、监听器和清理，并在应用层处理 SDK 未强制的策略。IMKit 优先使用文档化的 hook、主题、自定义视图和组件覆盖；过滤和自定义渲染不得改变底层同步范围。默认使用中文；Web IMKit 的官方默认值为 `zh_CN`。

### IMKit 就绪条件

写代码前先明确五个就绪条件的执行方式；运行时必须逐项满足后才能打开目标会话：

1. 初始化完成，且使用当前平台/SDK 版本文档化过的初始化 API。
2. Token 连接成功，连接失败、断线或重连未完成时不得继续。
3. 会话列表加载/同步完成；加载中、加载失败、同步返回 `39003` 或用户未进入会话页面时，不得提交打开会话操作。
4. 确认目标会话可打开，且会话类型、`targetId` 和业务权限匹配。目标平台文档要求从已加载列表选择或确认存在时，必须先满足该条件；目标平台文档明确允许打开列表外会话（例如 Web IMKit `openConversation`）时，禁止把“已存在”当成 SDK 硬性条件，但仍要先完成列表同步并校验参数与权限。
5. 打开目标会话。任何一步失败都必须展示错误或恢复路径，禁止假设成功、重放后续 API 或把 `39003` 一律当作可忽略错误。

初始化、连接、列表加载/同步和目标会话可打开性要有可观察状态或回调。连接状态从成功变为断开时，必须停止发送、打开会话等后续会话操作，清理待提交动作，待重新连接、列表重新同步并重新确认目标会话后再恢复。

### UI 组件所有权检查

使用 IMKit 时，优先确认目标组件由 IMKit 提供还是应用实现；需要替换 IMKit 内置行为时，优先使用该版本文档化的覆盖、slot、hook 或事件，不要在外层重复创建同类组件。仅调整样式或使用 IMKit 原生组件时，不需要填写所有权表。

采用 IMKit 与 IMLib/应用自有 UI 混合方案，或存在重复组件、职责不清时，填写下表并确保每个组件只有一个所有者：

| 组件 | 所有者 |
| --- | --- |
|  | IMKit / IMLib / 应用自有 UI / 不在本次范围 |

若能力归属或版本支持不明确，再按 [功能清单使用规则](./feature-lists.md) 获取目标平台 IMKit 功能清单并阅读相关功能页。

### IMLib 自定义 UI 实现要求

IMLib 只提供 SDK 能力时，自定义 UI 按本次需求实现，不强制枚举和实现所有可能的交互控件。已实现的交互必须调用对应 SDK API，并处理基本的加载状态和失败提示，不能只有静态展示。

SDK 调用失败时不得伪造成功。未实现的交互明确列为未实现或待复核，不宣称已支持。

### 截图驱动实现（IMKit）

收到 2 张或更多截图时，先执行 [截图分析指南](./image-analysis-guide.md) 的清点、丢弃品牌/营销、拆分认证/通话和去重流程，再按该指南定义的表结构输出完整差距表。功能分类与验证状态以 [功能模式映射](./feature-pattern-map.md) 为准，并根据目标平台的官方文档和项目安装版本补充说明。

在写代码前将差距表交给用户确认；对 Constrained 和 Unsupported 项明确说明接受限制、改用 IMLib 或放弃需求的取舍。确认后挂载 provider、应用配置并构建外围应用组件；不支持项必须明确告知并跳过，不得静默省略或编造变通方案。

## 测试与验证

在适用时构建或类型检查项目，并按本次变更验证核心路径：初始化与 Token 注入、连接及重连、目标会话、消息收发。仅当本次实现推送、未读、回执、提及、自定义消息或审核等能力时，再验证对应行为；IMKit 核对相关就绪条件，已填写所有权表时核对其结果。发布前提醒将调试日志调整为 WARN/ERROR。

构建、类型检查和单元测试只能证明静态正确性。包含自定义或编排 UI 时，条件允许则在目标运行环境验证至少一条与本次功能相关的用户路径；无法执行时说明未验证的路径和风险，不得宣称运行时验证通过。

## 最终待办处理

输出两份清单：

- **已实现功能**：按 Built-in、Configurable、Application chrome、Application-server 分组。
- **未实现功能**：

| 功能 | 状态 | 原因 |
| --- | --- | --- |
| 功能名称 | 未实现 / 不支持 / 范围外 / 待复核 | 简要说明 |

只使用上述状态值。若截图包含通话、会议、直播、登录/注册/2FA、第三方品牌元素或仅服务端功能，必须增加**范围外项目**部分，并说明对应归属或缺失条件。

## TODO 清单

列出仍需用户提供或后续完成的项目，例如 App Key、Token 端点、服务端队列、待验证 API、用户确认的源码修改或不支持的需求。

## 常见问题处理

若网络不可用，使用缓存或已安装代码并标记待复核；若官方文档和安装版本不一致，以安装版本为实现依据并报告冲突；若项目平台无法识别，只询问一个平台问题；若用户指定的 SDK 无法满足需求，说明限制，并在切换到另一 SDK 前获得同意。
